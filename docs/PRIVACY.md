## Summary

Honeypot Kit is a self-hosted, locally-operated tool. By default, all data
collected by the honeypot stays on the device where it is installed. The
Honeypot Kit project itself does not collect, transmit, or have access to
any data from your installation.

Optional integrations may send data to external services. You control which
integrations are enabled. This document describes what data is collected,
where it goes, and how you can control it.

---

## What Data Is Collected

Honeypot Kit captures data from systems that attempt to connect to the
honeypot's SSH port (port 22). This includes:

- **Source IP addresses** of connecting systems
- **Usernames and passwords** attempted during login
- **Shell commands** entered by attackers who reach the fake shell
- **File download URLs** attempted by attackers
- **Session metadata** - connection time, duration, session ID
- **System events** - connection established, disconnected, login success/failure

This data is generated by Cowrie, an SSH honeypot that presents a fake
shell environment to attackers. No real system access is granted.

**This data is attacker-generated.** It describes the behavior of systems
attempting unauthorized access to your honeypot. It is not data about you,
your users, or your legitimate network traffic.

---

## Where Data Is Stored

All collected data is stored locally on your Raspberry Pi at:

```
/opt/honeypot/cowrie/var/log/cowrie/cowrie.json   - structured event log
/opt/honeypot/cowrie/var/log/cowrie/cowrie.log    - plain text log
/opt/honeypot/integrations/openai/analysis/       - AI analysis results (if enabled)
```

No data is transmitted to the Honeypot Kit project, its maintainer, or any
third party unless you explicitly enable an integration that does so.

---

## Data Retention

Log files are rotated automatically:

- **Cowrie logs:** 7-day rotation by default (configurable via logrotate)
- **AI analysis results:** retained indefinitely until manually deleted
- **Monitor state:** `/opt/honeypot/monitor-state.json` - login alert flag only

To manually clear all collected data:

```bash
sudo systemctl stop cowrie
sudo rm -f /opt/honeypot/cowrie/var/log/cowrie/cowrie.json
sudo rm -f /opt/honeypot/cowrie/var/log/cowrie/cowrie.log
sudo rm -rf /opt/honeypot/integrations/openai/analysis/
sudo systemctl start cowrie
```

## What Leaves the Device

### Default configuration

Nothing. All data stays on the Pi.

### OpenAI integration (if installed and enabled)

When the OpenAI AI Session Analysis integration is enabled, Honeypot Kit
sends session data to the OpenAI API for analysis. The following data
is transmitted:

- Session event types and timestamps
- Commands entered by the attacker
- Usernames attempted (not passwords, by default)
- File download URLs observed
- Session duration and metadata

The following is **never sent** to OpenAI by default:

- Passwords attempted by attackers (redacted by default)
- Attacker IP addresses (configurable - redaction available)
- Your Pi's hostname, network configuration, or system details
- Any data from other Honeypot Kit installations

**OpenAI's privacy policy** governs how they handle data submitted to their
API: https://openai.com/policies/privacy-policy

To disable the OpenAI integration:
```bash
honeypot-kit ai disable
# or edit: /opt/honeypot/integrations/openai/config.json
# set "enabled": false
```

To enable IP address redaction before sending to OpenAI:
```bash
# Edit: /opt/honeypot/integrations/openai/config.json
# set "redact_ips": true
```

### Grafana integration (planned)

When the Grafana integration is available and enabled, attack metrics
(counts, rates, timestamps) will be sent to your configured Grafana/
Prometheus instance. This is self-hosted by default - data goes to a
server you control, not to Grafana Labs' cloud unless you configure it
that way.

### Future integrations

Each integration will document what data it transmits, to where, and how
to control it. This document will be updated as integrations are added.
The integration's Stage 1 document (in `docs/integrations/`) will always
describe data flows before you install it.

## Attacker Data and Privacy Law

The data collected by Honeypot Kit describes unauthorized access attempts
by third parties. In most jurisdictions this data is:

- **Not personal data about you** - it describes attackers, not legitimate users
- **Collected passively** - you are not soliciting or storing data about
  people who have a legitimate relationship with your system
- **Security-relevant** - collection of intrusion attempt data is generally
  permitted under computer security and network protection frameworks

However, IP addresses may be considered personal data in some jurisdictions
(particularly under GDPR in the European Union). If you are subject to GDPR
or similar regulations, consult your legal counsel regarding honeypot
operation and log retention.

**Honeypot Kit is an educational tool.** It is not designed for enterprise
security operations, legal evidence collection, or regulatory compliance
use cases. See [docs/THREAT_MODEL.md](THREAT_MODEL.md) for design scope.

## No Telemetry

Honeypot Kit does not include any telemetry, analytics, or usage tracking.
The project does not know how many installations exist, what attacks have
been seen, or anything about how you use the software.

The auto-update system (`honeypot-update.sh`) downloads files from GitHub
but does not send any data about your installation. It makes outbound HTTP
requests to `raw.githubusercontent.com` only.

## Your Controls

| Control | How |
|---------|-----|
| Disable all external data transmission | Don't install any integrations |
| Disable OpenAI integration | `honeypot-kit ai disable` or set `enabled: false` in config |
| Redact attacker IPs before OpenAI | Set `redact_ips: true` in OpenAI config |
| Redact passwords before OpenAI | Set `redact_passwords: true` (default: true) |
| Clear all logs | See "Data Retention" section above |
| Shorten log retention | Edit `/etc/logrotate.d/honeypot` |
| Stop honeypot entirely | `sudo systemctl stop cowrie` |
